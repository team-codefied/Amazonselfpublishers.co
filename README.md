# amazonselfpublishers website

Static HTML/CSS/vanilla-JS website with a PHP form backend, built for Hostinger shared hosting.
No framework, no runtime Node.js, no database.

## Layout

```
site/                  <- everything that gets uploaded to public_html
  index.html, *.html   <- generated pages (one per route)
  assets/css, js, img  <- styles, scripts, logo, book covers
  backend/             <- contact.php, token.php, lib.php, .env.example
  .htaccess            <- HTTPS, extensionless URLs, security headers, caching
  sitemap.xml, robots.txt
tools/                 <- dev only (never uploaded)
  build.mjs            <- page generator (templates + content)
  data/                <- config.mjs, services.mjs, misc.mjs (all copy and settings)
  audit.mjs            <- link/metadata/asset audit of the built output
  dev-router.php       <- local PHP server router (mimics .htaccess)
  fake-smtp.js         <- local SMTP sink for testing
  prep-images.js, trim-logo.js  <- image pipeline (needs `npm i` in tools/)
_backup_original_assets/  <- the rejected logo, the new-logo source and original cover files
PROJECT_STATUS.md, QA_REPORT.md, HOSTINGER_DEPLOYMENT.md
```

## Editing content

All business details live in `tools/data/config.mjs` (name, phone, domain, email, address, social links).
Service copy is in `tools/data/services.mjs`; books, blog posts, FAQs and testimonials in `tools/data/misc.mjs`.
After any change run:

```bash
node tools/build.mjs     # regenerates site/
node tools/audit.mjs     # checks links, assets, titles, h1s
```

The generator needs only Node 18+. The generated `site/` folder is plain files.

## Local preview (with working form backend)

Requires PHP 8+. To test email without a real mailbox, run the local SMTP sink:

```bash
node tools/fake-smtp.js &
MAIL_TO=owner@test.local MAIL_FROM=site@test.local SMTP_HOST=127.0.0.1 SMTP_PORT=2525 SMTP_SECURE=none \
  php -S 127.0.0.1:8080 -t site tools/dev-router.php
```

Open http://127.0.0.1:8080. Submitted messages are appended to `tools/smtp-received.txt`.

## Branding

The supplied logo is used unmodified (only the empty black margin was trimmed, which is not part of the artwork).
Because the logo has an opaque black background, the header, footer and landing header are black so the logo
sits seamlessly. The palette (gold `#f9b51d`, orange `#f58220`, black `#0b0b0c`, cream) is derived from the logo.
Tokens are CSS variables at the top of `site/assets/css/styles.css`.

## Troubleshooting

- **Form says "session expired"**: `backend/token.php` is not reachable (PHP disabled or wrong path).
- **"We could not send your message"**: SMTP settings in `backend/.env` are wrong; see HOSTINGER_DEPLOYMENT.md.
- **Page 404s on refresh**: `.htaccess` was not uploaded (it is a hidden file) or `mod_rewrite` is off.
- **Logo shows a black box on a light surface**: place it only on dark surfaces (the site already does).

## Form rules and how they are guarded
Every form on the site is generated by ONE function (`form()` in `tools/build.mjs`) and handled by ONE script (`site/assets/js/main.js`) and ONE endpoint (`site/backend/contact.php`). Name, Email, Phone and the privacy/terms acknowledgement checkbox (UNticked by default) are required; every other field (service, message, book title, manuscript status) is optional. Every submit button is followed by the KDP/non-affiliation disclosure (shared `DISCLOSURE_HTML` in `tools/build.mjs`).

After any change run both guards:

```bash
node tools/build.mjs
node tools/audit-forms.mjs     # parses EVERY form in the built HTML; fails if any form lacks required name/email/phone/consent (unticked), lacks the disclosure under its button,
                               # marks an optional field required, lacks its required marker, or isn't a .lead-form
node tools/test-backend.mjs    # needs the local server + fake SMTP running; 40 checks of the server-side rules and spam protection
```

To change the rules, change them in all three layers together: the `required` attributes and markers in `form()`, `validate()` in `main.js`, and the checks in `contact.php`. Do not add `<form>` markup anywhere else; use `form()` so the audit and the shared handler apply.

## Pages and routes (after the Microsoft Ads fix list, 2026-10-28)
- Every service uses ONE template (`servicePage()` in `tools/build.mjs`); per-service content and headings live in `tools/data/services.mjs`.
- **Book Publishing now lives at `/publishing-services`** (a neutral path without "amazon"; set by `route:` in `services.mjs`). The old `/book-publishing-services` is a permanent 301 redirect (`.htaccess`, generated by the build; mirrored in `tools/dev-router.php`). Menus, cards and the sitemap use the new path. Point the ad's final URL at `/publishing-services`.
- `/amazon-publishing-services` is a normal service page (same URL as before).
- The cover gallery exists only on the home page ("sample covers, not client projects"). Portfolio is the "Our Work" placeholder. Run `node tools/audit.mjs`; it fails if a gallery or draft notice reappears elsewhere.

- Services flagged `landing: true` in `tools/data/services.mjs` (currently Book Publishing only) use the landing-page template (`landing()`); all others use `servicePage()`.
